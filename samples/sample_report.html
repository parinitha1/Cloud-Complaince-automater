Check details

FAIL [critical] IAM-001 · Root account has MFA

The root user has unrestricted access, so it must be protected with MFA (hardware MFA preferred).

  • root: Root account has no MFA device

Fix: Register an MFA device for the root user and store break-glass access securely.

FAIL [critical] IAM-002 · Root account has no access keys

Root access keys cannot be scoped down and should not exist.

  • root: Root account has active access keys

Fix: Delete root access keys and use IAM roles or Identity Center users for programmatic access.

FAIL [critical] LOG-001 · CloudTrail multi-region trail is logging

At least one multi-region CloudTrail trail should be actively logging management events.

  • account: No trail is both multi-region and actively logging

Fix: Create a multi-region trail delivering to a protected S3 bucket and make sure logging is started.

FAIL [critical] RDS-001 · RDS not publicly accessible

Database instances should not be directly reachable from the internet.

  • prod-postgres: Instance is publicly accessible

Fix: Disable public accessibility and use private subnets with access through application tiers or a bastion.

FAIL [critical] S3-001 · S3 buckets block public access

All four S3 Block Public Access settings should be enabled so objects cannot be exposed by ACLs or policies.

  • acme-customer-exports: Block Public Access not fully enabled; missing: block_public_acls, ignore_public_acls, restrict_public_buckets
  • acme-app-logs: Block Public Access not fully enabled; missing: block_public_acls, ignore_public_acls, block_public_policy, restrict_public_buckets

Fix: Enable Block Public Access on the bucket (or the whole account): BlockPublicAcls, IgnorePublicAcls, BlockPublicPolicy, RestrictPublicBuckets.

FAIL [critical] SG-001 · No world-open SSH/RDP

Security groups must not allow 0.0.0.0/0 or ::/0 to reach SSH (22) or RDP (3389), including via all-traffic rules.

  • ap-south-1:sg-0a1 (web-sg): World-open admin port(s): 22
  • us-east-1:sg-0c3 (legacy-open): World-open admin port(s): 22, 3389

Fix: Restrict the source to a VPN or bastion CIDR, or use SSM Session Manager and remove the rule.

FAIL [high] ENC-001 · EBS volumes encrypted

EBS volumes should be encrypted at rest.

  • vol-0aa1: Volume is not encrypted

Fix: Create encrypted snapshots/copies and replace unencrypted volumes; enable EBS encryption by default per region.

FAIL [high] ENC-002 · RDS storage encrypted

RDS instances should have storage encryption enabled.

  • prod-postgres: Storage is not encrypted

Fix: Encryption cannot be turned on in place: restore from an encrypted snapshot copy and cut over.

FAIL [high] IAM-004 · Console users have MFA

Every IAM user with console access should authenticate with MFA.

  • bob: Console access without MFA

Fix: Require MFA for all console users, or move to federated sign-in with enforced MFA.

FAIL [high] S3-002 · S3 buckets use default encryption

Buckets should encrypt objects at rest by default (SSE-S3 or SSE-KMS).

  • acme-customer-exports: No default encryption configured

Fix: Enable default bucket encryption, preferably SSE-KMS with a customer-managed key for sensitive data.

FAIL [high] SG-002 · No world-open ports other than 80/443

Only public web ports should be reachable from the whole internet. Admin ports are reported by SG-001.

  • ap-south-1:sg-0b2 (db-sg): World-open: tcp/5432-5432

Fix: Narrow the source CIDR to known ranges or place the service behind a load balancer or private network.

FAIL [medium] BCK-001 · RDS automated backups retained

Automated backups should be kept for at least the configured number of days (default 7).

  • prod-postgres: Backup retention 1 days, expected at least 7

Fix: Raise the backup retention period on the instance.

FAIL [medium] ENC-003 · KMS customer keys rotate

Customer-managed symmetric KMS keys should have automatic rotation enabled.

  • ap-south-1:1234abcd-aaaa-bbbb-cccc-1234567890ab: Automatic rotation disabled

Fix: Enable automatic key rotation on each customer-managed key.

FAIL [medium] IAM-003 · Strong password policy

The account password policy should require a minimum length that meets your standard (default 14).

  • account: Minimum length is 8, expected at least 14

Fix: Update the IAM account password policy to meet the minimum length and require varied character types.

FAIL [medium] IAM-005 · Access keys rotated

Active access keys should be rotated at least every 90 days (configurable).

  • bob/AKIAEXAMPLEBOB1: Key is 412 days old (limit 90)

Fix: Rotate or delete stale keys; prefer short-lived credentials from roles.

FAIL [medium] IAM-006 · No directly attached admin policy on users

Users should receive privileges through roles or groups, not by attaching AdministratorAccess to the user.

  • bob: AdministratorAccess attached directly to user

Fix: Detach AdministratorAccess from the user and grant least-privilege access through reviewed roles or groups.

FAIL [medium] LOG-002 · CloudTrail log file validation

Log file integrity validation lets you detect tampering with delivered logs.

  • regional-trail: Log file validation disabled

Fix: Enable log file validation on every trail.

FAIL [medium] LOG-003 · CloudTrail logs encrypted with KMS

Trail logs should be encrypted with a KMS key rather than only default S3 encryption.

  • regional-trail: Trail is not encrypted with a KMS key

Fix: Set a KMS key on the trail and grant CloudTrail permission to use it.

FAIL [medium] LOG-004 · Log groups retain logs long enough

CloudWatch log groups should keep logs for the period your policy requires (default 365 days). 'Never expire' passes.

  • ap-south-1:/app/prod: Retention 14 days, expected at least 365

Fix: Set the log group retention to at least the required number of days or export logs to long-term storage.

FAIL [medium] RES-001 · Data stores are in approved regions

Storage and databases should sit in regions your data residency policy allows. This is a visibility check: the DPDP Act does not by itself bar storing data outside India, but sector regulators or contracts may. Skipped unless allowed regions are configured.

  • acme-customer-exports: In us-east-1; allowed: ap-south-1, ap-south-2

Fix: Move data to an approved region, or document the legal basis for keeping it elsewhere.

FAIL [medium] S3-003 · S3 bucket versioning enabled

Versioning protects against accidental deletion and overwrite, supporting recovery.

  • acme-customer-exports: Versioning is not enabled

Fix: Enable versioning, and add lifecycle rules to expire old versions according to your retention policy.

FAIL [medium] S3-005 · S3 bucket policy enforces TLS

Bucket policies should deny requests that do not use HTTPS (aws:SecureTransport = false).

  • acme-customer-exports: No policy statement denying non-TLS requests
  • acme-app-logs: No policy statement denying non-TLS requests

Fix: Add a Deny statement for Principal * with condition Bool aws:SecureTransport = false.

FAIL [low] S3-004 · S3 server access logging enabled

Access logs give an audit trail of requests to each bucket.

  • acme-customer-exports: Server access logging is not enabled
  • acme-app-logs: Server access logging is not enabled

Fix: Enable server access logging to a dedicated log bucket, or use CloudTrail data events for sensitive buckets.
